# Путь кластера — вебинар о платформе

Интерактивная HTML-презентация о создании Kubernetes-кластера: от `ClusterClaim` и подготовки инфраструктуры до готового L2 и приложений пользователя. Основной вариант — **[platform-beget.html](outputs/platform-beget.html)**, оформленный в стилистике Beget с космическим фоном. Рассказ рассчитан на 10–15 минут: 7 глав, 36 событий, ручное переключение шагов.

[Сценарий и заметки ведущего](outputs/platform-beget-guide.md) · [Предпросмотр](outputs/platform-beget-preview.png)

## Быстрый запуск

Для разработки и сборки нужны **Node.js `^22.18.0 || >=24.0.0`**, npm и современный браузер. Для клонирования — Git и доступ к репозиторию через SSH.

```bash
git clone git@github.com:PRO-Robotech/platform-webinar.git
cd platform-webinar
npm ci
npm run dev
```

Откройте в браузере **[http://127.0.0.1:5173/](http://127.0.0.1:5173/)**. Vite следит за изменениями исходников и обновляет страницу во время разработки. Чтобы остановить сервер, нажмите `Ctrl+C` в его терминале.

Если порт 5173 уже занят, укажите другой:

```bash
npm run dev -- --port 5174
```

Тогда адрес презентации будет [http://127.0.0.1:5174/](http://127.0.0.1:5174/).

**Без Node.js и сервера:** готовый файл `outputs/platform-beget.html` можно открыть напрямую в браузере. Стили, скрипты, логотип и шрифты встроены в HTML; для показа этого файла подключение к интернету не требуется. Репозиторий содержит готовую сборку, поэтому пересобирать её перед первым показом не нужно.

Приложение написано на TypeScript и использует Vite без UI-фреймворка и backend. Node.js нужен только для разработки и сборки; результат — обычные HTML, CSS и JavaScript.

## Управление

| Действие | Управление |
| --- | --- |
| Следующее событие | `→`, `PageDown`, пробел или кнопка перехода вперёд |
| Предыдущее событие | `←`, `PageUp` или кнопка перехода назад |
| Перейти к главе | Клавиши `1`–`7` или название главы в нижней панели |
| Выбрать событие внутри главы | Точки навигации в нижней панели |
| Открыть описание блока | Нажатие на блок; с клавиатуры — `Enter` или пробел на выбранном блоке |
| Закрыть описание | `Esc` или кнопка закрытия |
| Сменить оформление | Переключатель «Вид» в верхней панели; текущая глава и шаг сохраняются |
| Полный экран | `F` (или `А` в русской раскладке), кнопка `⛶`; также можно использовать `F11` браузера |
| Вернуться ко вступлению | `Home` или логотип Beget |
| Перейти к последнему событию | `End` |

События не перелистываются автоматически. Фоновая анимация работает независимо от переключения шагов и отключается, если в системе включено уменьшение движения.

На конкретный шаг можно сослаться через адрес, например:

```text
http://127.0.0.1:5173/#chapter-4-step-1
```

## Что показано в презентации

| Уровень | Роль |
| --- | --- |
| **L0 — управляющий кластер** | `ClusterClaim` задаёт целевую конфигурацию. ClusterClaim Operator координирует процесс, создаёт ресурсы `Cluster` и служебные компоненты CSR approver / CCM. Cluster API управляет созданием кластеров. |
| **L1 — инфраструктурный кластер** | Размещает инфраструктурные компоненты, Argo CD, AddonOperator и control plane L2 как приложение. Аддоны по фазам готовят защищённую платформу. |
| **L2 — клиентский кластер** | Предоставляет пользователю Kubernetes API и среду для приложений. Control plane L2 физически размещается в L1. |

Отдельно раскрыты взаимодействие с облаком и Vault, цепочка `AddonClaim → Addon → Applications → приложение` и передача статусов обратно по ресурсам. Подробности и реплики для выступления находятся в [сценарии ведущего](outputs/platform-beget-guide.md).

## Изменение и сборка

Редактируйте содержание в `src/content.ts`, а схемы — в `src/graphs-a.ts` и `src/graphs-b.ts`. Модуль `src/flow.ts` объединяет их в общий сценарий для всех вариантов оформления. Основная HTML-оболочка находится в `index.html`, оболочки сохранённых вариантов — в `templates/`. Команды выполняются из корня репозитория:

```bash
npm run typecheck
npm run build
npm run check:versions
```

`npm run typecheck` проверяет типы без создания файлов сборки. `npm run build` также включает проверку типов, затем собирает сайт через Vite и обновляет все девять HTML-вариантов и сценарии ведущего в `outputs/` из общего сценария. `npm run check:versions` проверяет согласованность содержания собранных версий. После пересборки обновите открытую готовую презентацию в браузере.

Чтобы локально посмотреть собранный сайт:

```bash
npm run preview
```

Откройте **[http://127.0.0.1:4173/](http://127.0.0.1:4173/)**. Если порт занят, используйте `npm run preview -- --port 4174` и адрес `http://127.0.0.1:4174/`. Сервер просмотра останавливается через `Ctrl+C`.

Для размещения на статическом хостинге отдавайте содержимое `dist/`. В нём находятся `index.html`, каталог `assets/`, все варианты презентации, сценарии и сохранённые PNG-предпросмотры. Материалы из `outputs/` доступны и в корне `dist/`, и в `dist/outputs/`, чтобы существующие ссылки продолжали работать. Относительная база путей `./` позволяет разместить сборку в подкаталоге. Навигация хранится в hash (`#chapter-4-step-1`), поэтому правила перенаправления маршрутов не требуются. Production-серверу не нужен Node.js.

## Сохранённые варианты

Все варианты используют актуальный общий сценарий: **7 глав и 36 событий**, одинаковые тексты, связи, последовательность действий и передачу статусов. Различаются оформление и способ показа. Суффикс `v1` обозначает сохранённый вариант оформления, а не устаревший сценарий.

Переключатель **«Вид»** доступен в верхней панели каждого варианта. Он открывает выбранное оформление на той же главе и шаге. При показе без сервера храните HTML-файлы рядом в одной папке, как в `outputs/`, чтобы переходы между ними работали.

- [Beget · Атлас](outputs/platform-beget-atlas.html) — язык звёздного атласа: одна сетка, одна шкала кеглей, янтарный цвет только для текущего события. [Сценарий](outputs/platform-beget-atlas-guide.md) · [Предпросмотр](outputs/platform-beget-atlas-preview.png).
- [Светлый Beget, v1](outputs/platform-beget-light-v1.html).
- [Тёмная история](outputs/platform-story.html) и [сохранённая тёмная версия v1](outputs/platform-story-dark-v1.html).
- [Космический маршрут](outputs/platform-flight.html) и [сохранённая версия v1](outputs/platform-flight-v1.html).
- [Первоначальная презентация](outputs/platform-webinar.html) и [классическая версия](outputs/platform-webinar-classic.html).

### Beget · Атлас

Во время разработки «Атлас» открывается из исходников: после `npm run dev` перейдите на [http://127.0.0.1:5173/outputs/platform-beget-atlas.html](http://127.0.0.1:5173/outputs/platform-beget-atlas.html). Изменения в `src/versions/atlas-*.ts` и `templates/atlas/` подхватываются без пересборки.

Положения блоков, зон и связей «Атласа» заданы в `src/versions/atlas-layout.ts`, отдельно от общего сценария: у каждой главы своя равномерная сетка колонок, одинаковые зазоры и одна высота блока. Если в `src/content.ts` или `src/graphs-*.ts` появится новый блок или зона, `npm run check:versions` сообщит, что для «Атласа» его нужно разместить. `Shift+G` показывает сетку поверх кадра. Кнопка с солнцем или луной в шапке (или клавиша `T`) переключает светлую и тёмную тему; выбор запоминается в браузере.

Все сохранённые HTML-варианты находятся в `outputs/` и открываются напрямую в браузере. `npm run build` обновляет их содержание одновременно, сохраняя оформление каждой версии. Не редактируйте готовые HTML вручную: следующие сборки создадут их заново из общего сценария и шаблонов.
