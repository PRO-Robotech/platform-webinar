# Путь кластера — вебинар о платформе

Интерактивная HTML-презентация о создании Kubernetes-кластера: от `ClusterClaim` и подготовки инфраструктуры до готового L2 и приложений пользователя. Основной вариант — **[platform-beget.html](outputs/platform-beget.html)**, оформленный в стилистике Beget с космическим фоном. Рассказ рассчитан на 10–15 минут: 7 глав, 36 событий, ручное переключение шагов.

[Сценарий и заметки ведущего](outputs/platform-beget-guide.md) · [Предпросмотр](outputs/platform-beget-preview.png)

## Быстрый запуск

Для разработки и сборки нужны **Node.js `^22.18.0 || >=24.0.0`**, npm и современный браузер. Для клонирования — Git и доступ к репозиторию через SSH.

```bash
git clone git@github.com:PRO-Robotech/platform-webinar.git
cd platform-webinar
npm ci
npm run dev
```

Откройте в браузере **[http://127.0.0.1:5173/](http://127.0.0.1:5173/)** — по умолчанию открывается «Beget · Атлас»; «Beget · Космос» из исходников доступен на [http://127.0.0.1:5173/index.html](http://127.0.0.1:5173/index.html). Vite следит за изменениями исходников и обновляет страницу во время разработки. Чтобы остановить сервер, нажмите `Ctrl+C` в его терминале.

Если порт 5173 уже занят, укажите другой:

```bash
npm run dev -- --port 5174
```

Тогда адрес презентации будет [http://127.0.0.1:5174/](http://127.0.0.1:5174/).

**Без Node.js и сервера:** готовые файлы `outputs/platform-beget-atlas.html` и `outputs/platform-beget.html` можно открыть напрямую в браузере. Стили, скрипты, логотип и шрифты встроены в HTML; для показа этого файла подключение к интернету не требуется. Репозиторий содержит готовую сборку, поэтому пересобирать ее перед первым показом не нужно.

Приложение написано на TypeScript и использует Vite без UI-фреймворка и backend. Node.js нужен только для разработки и сборки; результат — обычные HTML, CSS и JavaScript.

## Управление

| Действие | Управление |
| --- | --- |
| Следующее событие | `→`, `PageDown`, пробел или кнопка перехода вперед |
| Предыдущее событие | `←`, `PageUp` или кнопка перехода назад |
| Перейти к главе | Клавиши `1`–`7` или название главы в нижней панели |
| Выбрать событие внутри главы | Точки навигации в нижней панели |
| Открыть описание блока | Нажатие на блок; с клавиатуры — `Enter` или пробел на выбранном блоке |
| Закрыть описание | `Esc` или кнопка закрытия |
| Сменить оформление | Переключатель «Вид» в верхней панели; текущая глава и шаг сохраняются |
| Полный экран | `F` (или `А` в русской раскладке), кнопка `⛶`; также можно использовать `F11` браузера |
| Вернуться ко вступлению | `Home` или логотип Beget |
| Перейти к последнему событию | `End` |

События не перелистываются автоматически. Фоновая анимация работает независимо от переключения шагов и отключается, если в системе включено уменьшение движения.

На конкретный шаг можно сослаться через адрес, например:

```text
http://127.0.0.1:5173/#chapter-4-step-1
```

## Что показано в презентации

| Уровень | Роль |
| --- | --- |
| **L0 — управляющий кластер** | `ClusterClaim` задает целевую конфигурацию. ClusterClaim Operator координирует процесс, создает ресурсы `Cluster` и служебные компоненты CSR approver / CCM. Cluster API управляет созданием кластеров. |
| **L1 — инфраструктурный кластер** | Размещает инфраструктурные компоненты, Argo CD, AddonOperator и control plane L2 как приложение. Аддоны по фазам готовят защищенную платформу. |
| **L2 — клиентский кластер** | Предоставляет пользователю Kubernetes API и среду для приложений. Control plane L2 физически размещается в L1. |

Отдельно раскрыты взаимодействие с облаком и Vault, цепочка `AddonClaim → Addon → Applications → приложение` и передача статусов обратно по ресурсам. Подробности и реплики для выступления находятся в [сценарии ведущего](outputs/platform-beget-guide.md).

## Изменение и сборка

Редактируйте содержание в `src/content.ts`, а схемы — в `src/graphs-a.ts` и `src/graphs-b.ts`. Модуль `src/flow.ts` объединяет их в общий сценарий для всех вариантов оформления. Основная HTML-оболочка находится в `index.html`, оболочки сохраненных вариантов — в `templates/`. Команды выполняются из корня репозитория:

```bash
npm run typecheck
npm run build
npm run check:versions
```

`npm run typecheck` проверяет типы без создания файлов сборки. `npm run build` также включает проверку типов, затем собирает сайт через Vite и обновляет все девять HTML-вариантов и сценарии ведущего в `outputs/` из общего сценария. `npm run check:versions` проверяет согласованность содержания собранных версий. После пересборки обновите открытую готовую презентацию в браузере.

Чтобы локально посмотреть собранный сайт:

```bash
npm run preview
```

Откройте **[http://127.0.0.1:4173/](http://127.0.0.1:4173/)**. Если порт занят, используйте `npm run preview -- --port 4174` и адрес `http://127.0.0.1:4174/`. Сервер просмотра останавливается через `Ctrl+C`.

Для размещения на статическом хостинге отдавайте содержимое `dist/`. В нем находятся `index.html` (это «Атлас», вид по умолчанию; «Космос» лежит рядом как `platform-beget.html`), каталог `assets/`, все варианты презентации, сценарии и сохраненные PNG-предпросмотры. Материалы из `outputs/` доступны и в корне `dist/`, и в `dist/outputs/`, чтобы существующие ссылки продолжали работать. Относительная база путей `./` позволяет разместить сборку в подкаталоге. Навигация хранится в hash (`#chapter-4-step-1`), поэтому правила перенаправления маршрутов не требуются. Production-серверу не нужен Node.js.

### Docker

```bash
docker compose up --build -d
```

Сайт откроется на **[http://localhost:8080/](http://localhost:8080/)**. Другой порт задается переменной `PORT`, например `PORT=9000 docker compose up --build -d`. Остановить: `docker compose down`.

`Dockerfile` собирает сайт в `node:24-slim` командой `npm run build:release`: сборка, печать обоих PDF «Атласа» и картинки для превью ссылок через Chromium из свежей сборки и копирование их в `dist/`. Готовый `dist/` отдает nginx со стандартной конфигурацией; Chromium в итоговый образ не попадает. Обновлять PDF вручную перед сборкой образа не нужно.

## Сохраненные варианты

Все варианты используют актуальный общий сценарий: **7 глав и 36 событий**, одинаковые тексты, связи, последовательность действий и передачу статусов. Различаются оформление и способ показа. Суффикс `v1` обозначает сохраненный вариант оформления, а не устаревший сценарий.

Переключатель **«Вид»** доступен в верхней панели каждого варианта, кроме «Атласа»: он открывается по умолчанию и собственного переключателя не имеет, но остальные варианты ссылаются на него. Он открывает выбранное оформление на той же главе и шаге. При показе без сервера храните HTML-файлы рядом в одной папке, как в `outputs/`, чтобы переходы между ними работали.

- [Beget · Атлас](outputs/platform-beget-atlas.html) — язык звездного атласа: одна сетка, одна шкала кеглей, синий акцент только для текущего события, светлая и темная тема, скачивание PDF. Открывается по умолчанию. [Сценарий](outputs/platform-beget-atlas-guide.md) · [Предпросмотр](outputs/platform-beget-atlas-preview.png).
- [Светлый Beget, v1](outputs/platform-beget-light-v1.html).
- [Темная история](outputs/platform-story.html) и [сохраненная темная версия v1](outputs/platform-story-dark-v1.html).
- [Космический маршрут](outputs/platform-flight.html) и [сохраненная версия v1](outputs/platform-flight-v1.html).

### Beget · Атлас

Во время разработки «Атлас» открывается из исходников: после `npm run dev` откройте [http://127.0.0.1:5173/](http://127.0.0.1:5173/) (тот же вид доступен и по пути готового файла, `/outputs/platform-beget-atlas.html`). Изменения в `src/versions/atlas-*.ts` и `templates/atlas/` подхватываются без пересборки.

Положения блоков, зон и связей «Атласа» заданы в `src/versions/atlas-layout.ts`, отдельно от общего сценария: у каждой главы своя равномерная сетка колонок, одинаковые зазоры и одна высота блока. Если в `src/content.ts` или `src/graphs-*.ts` появится новый блок или зона, `npm run check:versions` сообщит, что для «Атласа» его нужно разместить. `Shift+G` показывает сетку поверх кадра. Кнопка с солнцем или луной в шапке (или клавиша `T`) переключает светлую и темную тему; выбор запоминается в браузере.

PDF для раздачи: `npm run export:pdf` печатает собранный «Атлас» в `outputs/platform-beget-atlas.pdf` (темная тема) и `outputs/platform-beget-atlas-light.pdf` (светлая) — по 8 страниц (звездная карта и 7 глав в законченном виде), без интерфейса: схема, таймлайн и логотип Beget. Кнопка скачивания в шапке отдает PDF в текущей теме; `npm run build` копирует оба файла в `dist/`, а `npm run build:release` делает все сразу: сборку, печать PDF, картинку превью и копирование.

Все страницы закрыты от индексации (`noindex, nofollow`) и несут Open Graph-разметку для превью ссылок. Картинка превью `outputs/platform-og.png` (1200×630) — звездная карта платформы с вопросом вебинара — рисуется командой `npm run export:og` (шаблон в `templates/og/`, сцена в `src/versions/og-entry.ts`). Абсолютные адреса в разметке строятся от `https://k8s.beget.xlsft.ru`; другой адрес задается переменной `SITE_URL` при сборке. Нужен установленный Chrome или Chromium (путь можно задать в `CHROME_PATH`). Те же страницы получаются при печати страницы из браузера («Сохранить как PDF»).

Все сохраненные HTML-варианты находятся в `outputs/` и открываются напрямую в браузере. `npm run build` обновляет их содержание одновременно, сохраняя оформление каждой версии. Не редактируйте готовые HTML вручную: следующие сборки создадут их заново из общего сценария и шаблонов.
